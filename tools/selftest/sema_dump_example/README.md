# `--emit=sema` 的样例对（S03 起）

这三份文件是**规范的可执行版本**：`docs/prompts/S03-01-任务prompt.md` §五 那个
"完整例子"的排版曾经与规则文字自相矛盾（把类型记号写在运算符之后、把下标内联到
同一行），而 §六 第 4 条的"去注解还原"判据又要求两者必须一致——**不可能同时成立**。

现在它们一致了，而且这个一致性是**机械验证过的**（不是靠人眼比对）：

```
example.sy              源码
example.emit-ast.txt    该源码真实的 --emit=ast 输出（60 行，冻结格式）
example.emit-sema.txt   §五 的期望 --emit=sema 输出（76 行）

不变式：对 example.emit-sema.txt 按 §六 第 4 条的三步去注解
        → 必须与 example.emit-ast.txt 逐字节相同
```

## 怎么用

1. 先写还原器，在三份文件上跑通（**这是最便宜的调试环境**，不用等编译器写完）。
2. 再让 `--emit=sema` 的输出与 `example.emit-sema.txt` **逐字节相同**。
3. 最后把还原器接到全部 490 个用例上。

## 两个坑（都是实测踩出来的）

* **顺序**：必须先处理 `Cast`，再删记号。`Cast` 头上的目标类型记号与值类型记号
  拼写完全相同，先删记号会把 `(Cast :IntToFloat :float` 咬成 `(Cast :IntToFloat`，
  规则再也匹配不上。
* **结构感知**：`(Decl :const :int` 与 `(FuncDef f :float` 上的类型记号是 S02 原有
  格式的一部分，**不在删除之列**。

两者的报错症状相同：**还原结果比基础输出多出一个"只含缩进的空行"**。
看到这个症状，先怀疑还原器，不是编译器。

## 为什么 `Cast` 要单独处理

其余三样（`:t`、`:obj`、值类型记号）都是**就地插入的记号**，删掉即还原。
`Cast` 不同——它加的是**一个节点**，按冻结布局独占一行、子节点在下一行缩进 +2。
所以"换成子节点" = 删掉 `Cast` 那一整行 + 把子节点子树**每一行**去掉 2 个前导空格。
